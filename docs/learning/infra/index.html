The route ahead

Proof unlocks the next step
  1. Start here · 8 min

    Trace the running system

    You learn: Follow HTTP, admission, socket calls and returned PNGs. Locate the failure boundary.

    Move on when: Explain why browsing survives a stopped renderer. Compare private liveness with readiness.

  2. Next · 8 min

    Identify exactly what we ship

    You learn: Connect Go binaries, build stages, two images, three services and the retained release archive.

    Move on when: Find the source revision, two image IDs and checksums; distinguish CI verification from deployment.

  3. Then · 10 min

    Rehearse release decisions

    You learn: Predict smoke, drain, replacement and rollback. Separate persistent storage from process memory.

    Move on when: Explain the response to a failed smoke, a stuck drain and failed candidate readiness.

  4. Stage 1 · local lab

    Prove local boundaries

    You learn: Run the isolated Compose rehearsal. Inspect mounts, health, permissions and actual limits.

    Move on when: Record actual results from make check-compose; reserve real OOM and capacity claims for the target host.

  5. Stage 1 · approved infrastructure

    Prepare state and the host

    You learn: Prove state locks and recovery; then review cloud objects, immutable bootstrap and forwarding policy.

    Move on when: Two-client state test, reviewed budget/plan, recovery access, IPv4/IPv6 and reboot evidence.

  6. Stage 1 · operating proof

    Deploy staging and restore it

    You learn: Operate live TLS, release and rollback; recover from independently stored files and volumes.

    Move on when: Staged release/rollback, target load/OOM, TLS persistence, timed second-machine restore and an alert recipient.

  7. Stage 2 · after measurements

    Improve a measured bottleneck

    You learn: Choose between accepting restarts, resizing, changing state ownership or adding renderer capacity.

    Move on when: A measured problem and a demonstrated improvement; one global admission story before multiple web replicas.

  8. Stage 3 · optional lab

    Learn a second operating model

    You learn: Map Compose to Kubernetes in a separate lab; examine what a scheduler does and what remains application work.

    Move on when: Compare rolling-update behaviour, queue ownership, RAM and recovery cost.
