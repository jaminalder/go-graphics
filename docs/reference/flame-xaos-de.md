# Flame transitions and density estimation

The flame engine uses a transition-weight table (xaos) to influence which transform follows the current transform. This lets a small IFS express different recurrent paths without replacing the whole attractor with independent randomly placed points. Transition selection and variations consume deterministic orbit streams. Source: [engine files](../../internal/flame/system.go) and [genome policy](../../internal/sketch/flame/genome_chaos.go).

Histogram development separates sampling from appearance. Flame's `--quality` sets samples per output pixel; `--aa` multiplies that budget. `--oversample` sets histogram resolution relative to the output. Logarithmic density is developed before optional density estimation; `--estimator` controls its maximum radius in output-pixel units, with minimum-radius and curve controls exposed by the sketch. Oversampled results are reduced to the output frame afterward.

These controls alter noise and edge reconstruction, not the deterministic camera. [The sketch reference](../sketches/016-flame.md) includes exact current flags and defaults. Compare the same seed and dimensions when evaluating estimator changes; compare equal-aspect resolutions when checking framing. The implementation's tests cover repeatability and estimator behavior; use the [performance guide](../performance.md) to measure the independent cost of orbit and development work.
